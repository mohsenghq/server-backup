- **The dead crates.io mirror in `~/.cargo/config.toml` is not a factor on this machine** — no `~/.cargo/config.toml` exists, and `index.crates.io` answered normally. The 2026-09-05 note below describes the previous machine; keep it for reference, and restore `~/.cargo/config.toml.bak` there if the mirror returns.
- **`ChunkerConfig` sizes are `usize`, not `u32`.** `fastcdc` 5.0 takes `usize`; converting at every call site was noise.
- **Phase 0 `ponytail` note in `snapshot.rs` resolved**: snapshot manifests are version-2 Merkle trees, not the Phase 0 flat file list. Repositories created before 2026-09-09 fail to open with `UnsupportedFormat` — expected, pre-1.0.
- **The index is a per-snapshot `SnapshotIndex` (`index/<id>.json`) rather than the single `index/pack.json` from an earlier draft**; GC treats every blob referenced by any live snapshot as reachable. It stays plaintext by design (hashes/sizes only, no content, no paths); encrypting it is one call site if reviewers prefer.
- **`aegis key-list` / `aegis key-remove` are flat subcommands, not an `aegis key <verb>` group.** They sit beside the already-shipped `aegis key-add` so nothing existing breaks and the commands match their flat neighbours (`init`, `replicate`, `backup`, `snapshots`). - **The in-process SFTP test server now sends real `st_mode` in the SFTP `permissions` field.** It previously OR'd only the file-type bits in, which is valid on the wire but not what any real server does — and it made `agentless.rs` fail here (see the session log). ## Known issues / open questions

_(anything that needs a second look, or a question for the user before proceeding)_

- **The merge, restore fix, and PROGRESS/ROADMAP updates are committed locally but not pushed**; CI has therefore still not run against the current tree (see next action).
- **This copy has no `.git` directory.** There is no history to consult and nothing can be committed until `git init` (or a fresh `git clone` of `https://github.com/mohsenghq/aegis`, which would also recover the history) — the user has not asked for either. Nothing in this session was committed. **So the CI fixes below are on disk but unverified by GitHub itself**: every job command was run locally instead (see the session log), and the two things that *cannot* be checked here are the Windows/macOS legs of the `test` job and the Tauri `desktop` bundle (no glib/webkit2gtk on this box, no Windows/macOS). Push the tree and read the first run before trusting the desktop job.
- **The `docker-tests` job pins `linuxserver/openssh-server:latest`,** which is exactly how the env-var breakage went unnoticed: the image changed the meaning of `PASSWORD_ACCESS` (now a boolean) and moved the password to `USER_PASSWORD`. `cargo test --workspace` skips this file without `AEGIS_DOCKER_TESTS=1`, so only the CI job exercises it. Pinning a tag (or digest) would make that failure mode visible in a diff instead of at run time.
- **This machine has no Rust toolchain by default and `/` is 98% full** (2.8 GB free on `/dev/nvme0n1p2`). The cold `target/` build is fine, but `cargo bench` in release plus a `cargo-fuzz` corpus will want headroom — check free space before starting the fuzzing phase.
- **Key rotation stops at the CLI on purpose.** The server can already hold a passphrase for the *catalog* sidecar key, but handing it a *repository* passphrase would make `aegis-server` a repository-key custodian, which `docs/10-security-model.md` never sanctions and which the RBAC matrix would have to grow a new admin-only surface for. The roadmap item ("key rotation / re-key flow") is satisfied by the documented, tested CLI. If an API route + UI affordance are wanted, raise it before building it.
- **Master-key rotation (re-key of the data itself) is deliberately not implemented.** Rotating a *passphrase* is the supported flow and is what `docs/10-security-model.md` specifies ("wrapped keys stored in the repo so the passphrase can be rotated without re-encrypting all data"). A true master-key rotation — generate a new master key, re-seal every blob, manifest and index under it — would mean rewriting the entire repository, with no rollback and no incremental progress, for a threat (passphrase compromise) that passphrase rotation does not actually address. Call it out in the Phase 7 security review if a reviewer disagrees.
- **The 10 s SFTP request timeout was a real long-backup bug, now fixed (see the session log).** `russh-sftp` aborts a session when a *single* request stalls longer than its timeout, and the default is 10 s; a WAN backup that lived for half an hour died on one slow packet with `i/o error at <stream>: Timeout`, having already written 796 MB. It is now a named constant (`sftp::SFTP_REQUEST_TIMEOUT_SECS = 120`) applied at both session-creation sites. There is **no regression test** for it: reproducing it needs a server that deliberately stalls one request, which the in-process harness cannot do. Worth a test if the value ever needs tuning.
- **Agentless throughput over a WAN is latency-bound, not bandwidth-bound.** Measured on the real host (~186 ms RTT): ~1 file/second and ~1.35 MB/s, which is the SFTP ceiling there — `russh-sftp` negotiates a 256 KiB max packet and the server caps it, so 256 KiB per round trip is all you get. `/etc /opt /var/backups` (1,689 files, 119 MB) took ~22 minutes; the whole box (`/root` = 45,643 files / 2.5 GB, `/usr/local` = 57,525 files / 1.6 GB) is a **multi-hour, realistically 10+ hour** job. Not a chunker problem and not fixable by raising a buffer: the cost is several sequential round trips *per file*, so it is small-file count that hurts. The real answers are agent mode (chunk at the source — which needs the target able to reach a repository, so the control plane needs an inbound-reachable repo, e.g. an `sftp://` location with a key the target holds) or excluding `node_modules`/caches from the path set. `docs/11-performance-targets.md` says nothing about the remote path, so none of this is a documented regression.
- **`aegis stats` under-reports `stored`.** The snapshot index records a blob's size only if that snapshot *wrote* it (`build_index` looks it up in the write map), so every deduplicated chunk is `size: None` and `stats()` counts it as 0. On the real backup below it reports `stored 647.3 KiB` for a repository that holds 803 MB on disk — the deduplicated data, i.e. exactly the part you care about, is the part being dropped. The fix is a `size(&str) -> u64` method on the `Backend` trait (only `LocalBackend` and `SftpBackend` implement it) plus a fallback in `stats()`; it is *not* done because `GET /metrics` calls `repo.stats()` on every Prometheus scrape, so this would turn a scrape into thousands of stat calls. That endpoint already re-derives the 64 MiB Argon2id key per scrape, which is its own problem. Fix both together, or neither.
- **`repo.rs` still carries a `crypto: None` branch for pre-encryption repositories** ("readable, but new writes stay plaintext until it is migrated"), with a comment pointing at a "Phase 6 re-key flow". That path is unreachable: `FORMAT_VERSION` 1 and `init` always encrypt, and PROGRESS.md already records that pre-2026-09-09 repos fail to open with `UnsupportedFormat`. Phase 6 being done, either delete the branch or state explicitly that plaintext→encrypted migration is dropped. Left untouched pending the user's call.
- **The audit log viewer is thin**: `GET /api/audit` returns the newest 200 entries with no filtering, paging, or time range, and the UI tab renders all of them. Enough to read a recent history; a real audit *investigation* needs filters. Not built — flagging rather than gold-plating.
- **The real-sshd integration tests have only been run locally with the Docker daemon unavailable (they skip); the CI `docker-tests` job is their first real execution — watch its first run.** Still true on this machine, and still worth watching: the SFTP `permissions` fidelity bug above was invisible to the in-process harness, so real-sshd is the only thing that can confirm the harness now matches sshd.
- **No mtime/size fast-path.** Every backup re-reads and re-hashes every file. Dedup means an unchanged tree writes nothing, but it does not yet approach "the speed of a metadata-only walk" as `docs/11-performance-targets.md` requires. The fast-path is described in `docs/03-repository-format.md`.
- **`restore` verifies by size only, not by re-hashing**; `aegis verify --deep` is the full-hash path.
- **Symlinks, hardlinks, empty directories, and non-regular files are skipped** by `backup`. Only regular files are captured. Needs a decision in Phase 1→2 transition on how to represent them in the tree format.
- **SFTP backend tests need a real SSH server** (`tests/sftp_server.rs` spins one up locally); confirm they pass in CI on all three runners.
- **Phase 5 desktop builds still cannot link on this box**: `aegis-desktop` (Tauri v2) fails at build time for missing `glib-2.0`/`webkit2gtk` system packages, so the workspace must be built with `--exclude aegis-desktop` here, as CI does. `cargo clippy`/`test`/`fmt` for the other five crates are unaffected.
